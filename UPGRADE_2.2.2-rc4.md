# Обновление до ЭВО.СНТ S3 2.2.2-rc4

Это промежуточный тестовый релиз для проверки исправления регистрации и heartbeat агентов распределённого нагрузочного тестирования.

## Требования

- Java 21+;
- существующая конфигурация ветки 2.2.x сохраняется;
- перед обновлением рекомендуется сохранить резервную копию текущего JAR и конфигурационных файлов;
- координатор и агенты рекомендуется тестировать на одной версии `2.2.2-rc4`.

## Обновление координатора — JAR

1. Остановить сервис координатора.
2. Сохранить резервную копию текущего JAR.
3. Установить `evo-snt-s3-2.2.2-rc4.jar`.
4. Запустить приложение с существующей конфигурацией.
5. Проверить `/actuator/health/readiness`.
6. Открыть `/agents` и убедиться, что API списка агентов не возвращает HTTP 500.

## Обновление агента — JAR

1. Остановить агент.
2. Сохранить резервную копию текущего JAR.
3. Установить `evo-snt-s3-2.2.2-rc4.jar`.
4. Запустить агент с параметрами режима AGENT, coordinator URL, registration token, адресом агента и identity file.
5. В журнале проверить успешную регистрацию агента.
6. Убедиться, что последующие heartbeat-запросы выполняются без HTTP 500.

Пример параметров запуска:

```text
-Dserver.port=8081
-Ds3perf.application-mode=AGENT
-Ds3perf.agent.coordinator-url=http://COORDINATOR:8080
-Ds3perf.agent.registration-token=<TOKEN>
-Ds3perf.agent.name=s3-agent-01
-Ds3perf.agent.address=http://AGENT:8081
-Ds3perf.agent.identity-file=/opt/s3perf/config/agent-identity.json
```

Registration token агента должен совпадать со значением `s3perf.distributed.registration-token`, настроенным на координаторе.

## Обновление Docker

Для prerelease используйте image с точным тегом версии:

```text
ghcr.io/phibus-dev/s3-performance-test-web:2.2.2-rc4
```

Не используйте `latest` для приёмочного тестирования prerelease.

## Приёмочная проверка

- координатор успешно запускается;
- агент успешно регистрируется;
- `/api/agents` возвращает HTTP 200;
- страница `/agents` отображает зарегистрированные агенты;
- heartbeat агента выполняется без HTTP 500;
- агент без явно заданного имени не вызывает `NullPointerException` на координаторе;
- время последней активности агента обновляется;
- агент доступен для выбора на `/distributed-tests`;
- распределённый тест запускается и завершается корректно;
- результаты и агрегированная статистика отображаются в UI.

## Откат

При необходимости остановите координатор и агенты и верните JAR/Docker image предыдущей проверенной версии. Если при установке `2.2.2-rc4` не выполнялись отдельные ручные изменения схемы БД, дополнительный rollback данных не требуется.
