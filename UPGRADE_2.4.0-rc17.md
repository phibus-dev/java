# Upgrade / test guide — 2.4.0-rc17

1. Остановите запуск новых тестов и дождитесь завершения активных прогонов.
2. Сохраните bootstrap-файл и резервную копию PostgreSQL.
3. Обновите Coordinator до `2.4.0-rc17` и перезапустите приложение. При запуске Flyway применит V24.
4. Убедитесь, что в `test_run` появились поля `latency_scope`, `latency_sample_count`, `api_request_*` и `object_*`.
5. Обновите все Agent JAR до `2.4.0-rc17`. Старые агенты остаются совместимыми, но распределённый запуск будет отмечен `LEGACY_MAX` вместо `HDR_HISTOGRAM`.
6. Выполните multipart upload одного объекта. В активном запуске должны отображаться три набора метрик:
   - `MULTIPART_PART` — latency отдельных частей;
   - `S3 API request` — latency create/upload/complete requests;
   - `Объектная операция end-to-end` — полная длительность загрузки объекта.
7. Сверьте число samples: число multipart samples равно числу загруженных частей, object operations — числу объектов. Cleanup delete не должен увеличивать API request count.
8. Выполните распределённый тест на двух rc17-агентах и проверьте `latencyAggregation=HDR_HISTOGRAM` в ответе `/api/distributed-tests`.
9. Откройте детали сохранённого S3-запуска и убедитесь, что новые метрики совпадают с финальным состоянием активного запуска.
10. На `/settings/configuration` экспортируйте открытый JSON и зашифрованный `.evos3`. В журнале HTTP не должно быть `password` в query string; `GET /api/config/export` должен вернуть 405.
11. Проверьте страницы Kafka M2/M4 со значениями, содержащими `<`, `>`, `&`, кавычки: они должны отображаться как текст.
12. Перед выпуском убедитесь, что Maven CI, CodeQL и Dependency Review успешны и настроены как required checks ветки `main`.

## Откат

Сначала остановите Coordinator и верните предыдущий JAR/image. V24 только добавляет столбцы, поэтому rc16 их игнорирует; удалять столбцы для оперативного отката не требуется. Перед любыми ручными изменениями схемы восстановите резервную копию PostgreSQL.

После отката верните все агенты к той же версии, что и Coordinator. Пользовательским клиентам, уже переведённым на POST export, обратный переход не требуется.
