# Upgrade / test guide — 2.4.0-rc11

1. Разверните JAR или Docker image 2.4.0-rc11 поверх rc10.
2. Новых миграций БД относительно rc10 нет.
3. Откройте основные разделы приложения и убедитесь, что логотип в шапке возвращает на главную страницу.
4. Откройте историю заданий и проверьте отображение не более 10 строк на странице и переходы между страницами.
5. Откройте Kafka `Consumer\Throughput` и проверьте новые названия `Producer -> Consumer` и `Runtime results`.
6. На странице Kafka Replication & KRaft запустите Replication Test для существующего topic.
7. Успешная проверка должна завершиться статусом `COMPLETED` и показать количество partitions, under-replicated, offline и нарушения min ISR.
8. Для проверки диагностики укажите недоступный topic или профиль без необходимых Kafka ACL: интерфейс должен показать статус `FAILED` и конкретную причину.
9. Проверьте журнал приложения: для синхронной серверной ошибки M3 должен присутствовать stack trace с сообщением `Kafka M3 request failed`.

Для выполнения Replication Test Kafka-пользователю необходимы права `DESCRIBE` на topic и доступ к описанию конфигурации topic. Для Partition Scaling дополнительно требуются права создания и удаления временных topics.
