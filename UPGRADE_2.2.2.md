# Обновление до ЭВО.СНТ S3 2.2.2

Версия 2.2.2 — стабильный релиз, подготовленный на основе успешно протестированной 2.2.2-rc4. Функциональных изменений относительно RC4 нет.

## Требования

- Java 21+;
- существующая конфигурация ветки 2.2.x сохраняется;
- перед обновлением рекомендуется сохранить резервную копию текущего JAR и конфигурационных файлов;
- координатор и все агенты рекомендуется обновить до одной версии 2.2.2;
- сохранить используемые значения `s3perf.distributed.registration-token` и параметры подключения агентов.

## Обновление координатора — JAR

1. Остановить сервис координатора.
2. Сохранить резервную копию текущего JAR и конфигурации.
3. Установить `evo-snt-s3-2.2.2.jar`.
4. Запустить приложение с существующей конфигурацией.
5. Проверить `/actuator/health/readiness`.
6. Проверить `GET /api/agents` — ожидается HTTP 200.
7. Открыть `/agents` и проверить отображение зарегистрированных агентов.
8. Проверить `/distributed-tests`.

## Обновление агента — JAR

1. Остановить агент.
2. Сохранить резервную копию текущего JAR.
3. Установить `evo-snt-s3-2.2.2.jar`.
4. Запустить агент с существующими параметрами AGENT mode.
5. Проверить журнал агента: регистрация/восстановление identity должны пройти успешно.
6. Убедиться, что heartbeat выполняется без HTTP 500.
7. На координаторе проверить обновление времени последней активности агента.

Пример запуска агента:

```text
java \
  -Dserver.port=8081 \
  -Ds3perf.application-mode=AGENT \
  -Ds3perf.agent.coordinator-url=http://COORDINATOR:8080 \
  -Ds3perf.agent.registration-token=<TOKEN> \
  -Ds3perf.agent.name=s3-agent-01 \
  -Ds3perf.agent.address=http://AGENT:8081 \
  -Ds3perf.agent.identity-file=/opt/s3perf/config/agent-identity.json \
  -jar evo-snt-s3-2.2.2.jar
```

Registration token агента должен совпадать со значением `s3perf.distributed.registration-token` на координаторе.

## Переход с 2.2.2-rc4

Переход с RC4 на stable 2.2.2 не требует изменения параметров приложения. Замените JAR/Docker image на stable-версию и перезапустите координатор и агентов. Функциональный код stable соответствует протестированному RC4; изменения release-ветки ограничены номером версии и release-документацией.

## Обновление Docker

Используйте стабильный image с точным тегом:

```text
ghcr.io/phibus-dev/s3-performance-test-web:2.2.2
```

Для production рекомендуется фиксировать тег `2.2.2`, а не полагаться только на `latest`.

## Приёмочная проверка после обновления

- координатор успешно запускается;
- readiness endpoint возвращает успешный статус;
- агент успешно подключается к координатору;
- `/api/agents` возвращает HTTP 200;
- `/agents` отображает зарегистрированные агенты;
- heartbeat выполняется без HTTP 500;
- время последней активности обновляется;
- агент доступен для выбора в `/distributed-tests`;
- распределённый S3-тест запускается и завершается корректно;
- агрегированная статистика и графики отображаются в UI;
- сохранённые задания корректно загружают параметры в форму;
- локальные S3-тесты работают без регрессий.

## Откат

При необходимости:

1. остановить координатор и агенты;
2. вернуть предыдущий проверенный JAR или Docker image;
3. восстановить предыдущую конфигурацию, если она изменялась вручную;
4. запустить сервисы и проверить readiness/heartbeat.

При обычном переходе с 2.2.2-rc4 на 2.2.2 отдельный rollback схемы данных не требуется, если при обновлении не выполнялись дополнительные ручные изменения БД.
