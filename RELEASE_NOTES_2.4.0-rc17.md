# ЭВО.СНТ S3 2.4.0-rc17

Семнадцатый release candidate версии 2.4.0 посвящён корректности нагрузочных метрик, защите конфигурации и воспроизводимости релиза.

## Изменения относительно rc16

### Однозначные S3 latency-метрики

- Сохранены прежние `p50LatencyMs`, `p95LatencyMs` и `p99LatencyMs`, но API теперь явно сообщает их `latencyScope` и `latencySampleCount`.
- Для multipart upload прежние перцентили имеют scope `MULTIPART_PART`: это длительность отдельных `UploadPart`, а не всего теста и не всей загрузки объекта.
- Добавлены отдельные p50/p95/p99 и счётчики для фактических S3 API requests и объектных end-to-end операций.
- Precondition upload и cleanup delete смешанных/циклических сценариев исключены из измеряемых API-метрик.
- Новые показатели сохраняются в истории и отображаются в карточке активного запуска и деталях истории.

### Корректная распределённая агрегация

- Агенты передают координатору сжатые HDR-гистограммы, а координатор объединяет распределения и вычисляет глобальные p50/p95/p99.
- Для агентов предыдущих версий сохранён совместимый fallback `LEGACY_MAX`; используемый способ агрегации возвращается в `latencyAggregation`.
- Размер и формат входящей гистограммы проверяются до сохранения статистики агента.

### Безопасность интерфейса и конфигурации

- `/api/config/export` принимает пароль только в `POST application/x-www-form-urlencoded`; устаревший GET отключён, чтобы секрет не попадал в URL и журналы доступа.
- Поле пароля экспорта очищается после завершения запроса.
- Динамические значения Kafka UI экранируются перед вставкой в HTML.
- Kafka M4 корректно выбирает профиль с признаком `defaultProfile`.

### CI и релиз

- Maven CI и CodeQL больше не маскируют нестабильность повторными полными сборками.
- Dependency Review теперь завершает workflow ошибкой для high-severity зависимостей и запрещённых лицензий.
- Release workflow запускается по тегу либо вручную только из `main`.
- Docker image создаётся из JAR, уже прошедшего `mvn clean verify`, без второй непроверенной Maven-сборки внутри Docker.

## Миграция и совместимость

Flyway применяет V24 и добавляет в `test_run` поля scope, sample count, API latency и object end-to-end latency. Старые записи получают вычисляемый scope и число прежних samples; новые API/object показатели для исторических записей остаются нулевыми.

Поля прежних перцентилей не удалены. Для истинной HDR-агрегации рекомендуется одновременно обновить Coordinator и все Agent до rc17; при смешанном составе координатор автоматически использует совместимый fallback.

GET-клиенты экспорта конфигурации должны перейти на POST. Формат экспортируемых JSON/`.evos3` файлов не изменён.
