# S3 Multipart Uploader (Java 21)

Приложение: S3MultipartUploader — демонстрационный утилитный класс на Java 21 для загрузки больших объектов в S3-совместимое хранилище с поддержкой кастомного endpoint.

Файл с исходным кодом: [S3MultipartUploader.java](/projects/S3MultipartUploader.java)

## Краткое описание

Программа генерирует поток случайных байт заданного размера (либо принимает размер как аргумент в байтах, либо выбирает случайный размер от 1 МБ до 10 ГБ) и загружает эти данные в указанный бакет S3.

- Если объект меньше минимального размера части (5 MiB), выполняется одиночный PutObject.
- Если объект ≥ 5 MiB — используется Multipart Upload: создаётся uploadId, данные отправляются частями (по умолчанию 64 MiB), собираются ETag каждой части и затем выполняется CompleteMultipartUpload.
- Для каждой части и для всей операции фиксируется время и рассчитывается скорость (MiB/s).
- В случае ошибки происходит логирование и попытка AbortMultipartUpload, чтобы не оставлять незавершённые multipart-upload'ы.

## Требования

- Java 21 (JDK)
- AWS SDK for Java v2 (s3 module). Пример для Maven/Gradle ниже.
- Доступ к S3-совместимому endpoint (AWS S3, MinIO и т.п.)

## Зависимости (пример)

Maven (pom.xml):

```xml
<dependency>
  <groupId>software.amazon.awssdk</groupId>
  <artifactId>s3</artifactId>
  <version>2.20.0</version> <!-- или новее -->
</dependency>
```

Gradle (build.gradle):

```groovy
implementation 'software.amazon.awssdk:s3:2.20.0'
```

## Конфигурация через переменные окружения

Приложение читает конфигурацию из переменных окружения:

- S3_BUCKET (обязательно) — имя бакета
- S3_REGION (обязательно) — регион (например, `us-east-1`)
- S3_ENDPOINT (опционально) — кастомный endpoint (например, `https://play.min.io`)
- S3_ACCESS_KEY (опционально) — access key для S3 (если требуется)
- S3_SECRET_KEY (опционально) — secret key для S3 (если требуется)

Если S3_ENDPOINT не задан — используется стандартный endpoint SDK для указанного региона.

## Сборка и запуск

1) Скомпилировать (пример вручную, если SDK доступен в classpath):

```bash
javac -cp "path/to/aws-sdk-jars/*" /projects/S3MultipartUploader.java
```

2) Запустить:

```bash
export S3_BUCKET="my-bucket"
export S3_REGION="us-east-1"
# опционально
export S3_ENDPOINT="https://play.min.io"
export S3_ACCESS_KEY="MINIOACCESS"
export S3_SECRET_KEY="MINIOSECRET"

# Запуск с генерацией случайного размера в диапазоне 1MB..10GB
java -cp ".:path/to/aws-sdk-jars/*" S3MultipartUploader

# Или передать конкретный размер в байтах как аргумент (например 10485760 = 10 MiB)
java -cp ".:path/to/aws-sdk-jars/*" S3MultipartUploader 10485760
```

Примечание: при использовании IDE/сборщика (Maven/Gradle) подключите зависимость как показано выше и запустите как обычное Java-приложение.

## Параметры работы и поведение

- Минимальный размер части для multipart: 5 MiB (требование S3 для всех частей, кроме последней).
- Размер части по умолчанию: 64 MiB (в коде константа DEFAULT_PART_SIZE). При необходимости можно изменить код для другого размера.
- Диапазон случайного размера: от 1 MiB до 10 GiB, если размер не передан через аргумент командной строки.
- Ключ (object key) формируется как `random-upload-<timestamp>.bin`.

## Логирование и метрики

- Для каждой части выводится:
  - Номер части
  - Размер части (байты)
  - ETag, возвращённый S3
  - Время загрузки части (ms)
  - Скорость загрузки части (MiB/s)
- По завершении multipart — выводится общее количество загруженных байт, общее время и средняя скорость (MiB/s).
- Ошибки логируются в stderr с stacktrace. При ошибке multipart-загрузки предпринимается попытка abort (s3.abortMultipartUpload).

## Обработка ошибок

- Исключения SDK (S3Exception) и IOException логируются и пробрасываются наружу (в main — выводится стек и приложение завершает работу).
- В блоке catch для multipart upload реализована попытка abort, чтобы не оставлять «зависшие» незавершённые загрузки.

## Рекомендации для продакшн-использования

- Для более надёжной и производительной загрузки использовать TransferManager (в AWS SDK v2) или реализовать параллельную загрузку частей (несколько потоков), контролировать retry/backoff и throttling.
- Подбирать размер части и степень параллелизма в зависимости от пропускной способности сети и требований к памяти/IO.
- Добавить более детальное логирование (например, через SLF4J/Logback) вместо System.out/err.
- При необходимости сохранять данные в файл перед загрузкой, если генерация потока не подходит для повторных попыток.

## Ограничения

- Программа последовательно загружает части — нет параллельной загрузки частей в исходном примере.
- Нет продвинутой retry-логики и адаптивного управления скоростью — это демонстрационный код для понимания процесса.

## Что можно добавить

- Параллельную загрузку частей (много потоков) с коллегиальным сбором завершённых частей;

- Настройки (часть/параллелизм/ключ) через конфигурационный файл или аргументы CLI;
- Интеграцию с мониторингом — экспорт метрик (Prometheus) или логирование в централизованный агрегатор.
