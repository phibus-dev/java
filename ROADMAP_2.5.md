# Roadmap 2.5

Цель ветки 2.5 — сделать распределённое нагрузочное тестирование устойчивым к рестартам,
упростить автоматизацию и добавить формальные критерии качества прогонов.

## M1 — Durable Coordinator

- Персистентный реестр Agent и management-state в PostgreSQL.
- Стабильная identity Agent после перезапуска Coordinator.
- Хранение только SHA-256 hash межсервисного токена Agent.
- Reconciliation состояния `BUSY` по telemetry активных run после рестарта.
- Flyway V25, интеграционные тесты и restart smoke.

## M2 — Единая модель запусков

- Общий жизненный цикл локальных и распределённых прогонов — реализован нормализованный runtime API.
- Персистентные assignments, статусы и причины остановки — реализовано для распределённых прогонов.
- Восстановление незавершённых запусков и явная reconciliation-политика — реализовано для Coordinator.
- Единые фильтры, история и повторный запуск в UI.

Текущий инкремент M2: `/api/runs` объединяет жизненный цикл локальных S3/ClickHouse/Kafka
и распределённых прогонов, включая единые статусы, временные метки, причины остановки и фильтры.
Локальная S3-история сохраняет фактический `stop_reason`; специализированные API остаются
обратно совместимыми. Flyway V26 продолжает хранить назначения и прогресс распределённых запусков,
а Coordinator восстанавливает их после рестарта.

## M3 — API и автоматизация

- Версионированная OpenAPI-спецификация.
- CLI для профилей, запуска, ожидания результата и экспорта отчёта.
- Идемпотентные команды и стабильные machine-readable ошибки.
- Контрактные тесты API и примеры для CI/CD.

## M4 — Критерии производительности

- SLO gates по throughput, latency и error rate.
- Переиспользуемые workload profiles и наборы сценариев.
- Сравнение с baseline и формальный pass/fail результата.
- Расширенные resource limits, UI E2E и эксплуатационная документация.

Каждый milestone выпускается через release candidate после зелёных unit, integration,
security и container smoke checks.
